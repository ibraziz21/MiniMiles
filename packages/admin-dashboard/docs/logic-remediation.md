# Logic remediation — 10 November 2026

Implemented and verified:

- Submit → Publish now accepts submitted funds/allocations. Deployed atomically to the source database after local PostgreSQL contract tests. Deployment preserved each live function body and changed only the publication-state condition. Current definitions/views were backed up under ignored `output/logic-deployment/`.
- Full paginated reads replace fixed reimbursement batch/incident, subscription payment and notification caps. Reimbursement reference lookups are chunked to avoid URL/default-row limits. A later-page failure rejects the operation rather than presenting partial totals. Subscription queue has 50-row navigation; canonical member directory has 50-row pages.
- Eligibility preview uses registered active verification templates and verified records, fails closed on failed history lookups and unsupported/malformed policies (including ANY policies), supports timezone-aware weekdays and returns an explicit unavailable response. **Audit correction:** cross-fund cooldown is intentional and preserved; historical `not_blocked` is intentionally unsupported by the database and remains refused.
- Members now use leaderboard usernames linked to Hub canonical identities, rather than the legacy wallet directory. Detail verifies a unique Hub mapping, reads Auth contact/join fields, sums the off-chain Miles ledger, shows paginated vouchers, latest 50 merchant ledger entries and linked deletion requests. Ambiguous/unavailable data fails visibly. Directory is restricted to identities linked to Hub accounts; no invented suspension status.
- Collections excludes future-due invoices. Older notifications resolve through the full campaign read instead of only the latest 50.
- Native-only opted-in users now qualify for campaigns through the existing dual-transport dispatcher; active web/native devices count once per user in the audience. Stats include both providers' accepted deliveries. Actual delivery still depends on configured native credentials and the worker; acceptance is not receipt/open confirmation.
- Merchant notes table and service-role permissions are deployed, with RLS and no public/member access.
- Receipt upload supports PDF/PNG/JPG up to 10 MB, MIME/signature validation, named production finance identity, submitted-batch checks, a private Storage bucket and five-minute signed access to the evidence actually linked to the batch. Existing external evidence references remain supported. Orphan uploads after abandoned forms do not yet have an automated retention job.
